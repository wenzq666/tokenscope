# 智能体与模型接入覆盖设计

版本 v16 · 2026-10-09 · v0.4.0 保留 56 个来源入口：28 个原生明确格式解析入口、3 个同步缓存解析入口、25 个真实用量导出入口。全部支持逐来源路径管理及规范/API 用量导入；仅 Cursor / TRAE 国际版增加实验性手动凭据同步。入口数不是本机已采集软件数。

依据产品设计需求中的智能体软件和模型清单整理。需求中的全部产品、平台和模型家族均纳入必须覆盖的接入目标；同时保留本设计原有清单。

初始计数口径保留：指定对话拆分为 12 个产品入口和 6 个平台入口，原有补充 8 项，共 26 个产品 / 平台目标；模型单独按 12 个家族规划。v0.3 合并 tokens 参考客户端，去除与初始清单重叠后新增 30 个来源入口，合计 56 个。桌面、IDE、CLI、网页是可区分的采集来源，不冒充 56 个独立品牌；TRAE 是 TraeCode / TraeWork 的品牌汇总，不能与两者重复累加。

本文“原生明确格式”表示已经实现对应字段、日期、身份与计量口径的解析和回归测试；它不等于厂商保证格式稳定，也不等于本机有该软件真实会话。“同步缓存”表示解析缓存结构，Antigravity 仍只读已有文件，Cursor / TRAE 国际版可在用户主动提供凭据后经特定接口生成缓存；不自动登录或抓浏览器 Cookie。“真实导出”要求来源提供实际计量，不能凭软件名、正文、请求数或积分造出 Token。机器实测结果另见 [开发状态](../docs/development-status.md)。

| Cursor | 已有同步缓存、实验性手动凭据 Dashboard 同步、官方 CSV、规范导入 | 非官方 OAuth；仅真实 Token 入库，Auto 未披露时保留未知，Credits 不换算；没有共享请求身份的缓存与 CSV 只选一个渠道 |
| GitHub Copilot | 原生 OTel chat span / inference details、显式 SDK assistant.usage、规范导入 | 真实调用身份跨渠道去重；普通无 usage 日志、上下文占用和 turn 汇总不作为消费，不宣称消费端完整自动采集 |
| TRAE · TraeCode | 已有同步缓存、国际 IDE / SOLO 实验性手动凭据同步、规范导入 | 非官方 OAuth，不解密本地库，不抓浏览器 Cookie；国内接口及 TraeWork 不复用，Auto 未披露底层模型时保持未知 |
| TRAE · TraeWork | 规范实际用量导入 | 未核实原生计量通道，不用办公任务数推算 |
| Manus | 规范实际用量导入 | 任务积分不换算 Token；无真实导出时不展示 |
| Gemini Deep Research | 规范实际用量导入 | 未接通云端账户；不按网页阅读量或正文猜 Token |
| Kimi | 规范实际用量导入 | 与 Kimi Code CLI 独立，不宣称已自动采集聊天消费端 |

规范导入统一支持全部目标，但前提是用户能从来源取得真实计量记录；它不表示各产品已经开放官方导出，也不表示已连接云端账户。无法读取真实 Token 的入口不伪造数值、不当成 0、不挤入软件用量表；在设置中展示状态与导入方式。格式见 [实际用量导入](../docs/public-usage-export.md)。

## v0.4.0 路径与连接边界

全部 56 入口在设置逐候选显示默认本地路径和“已发现 / 未发现”，包括当前没有用量的来源。点击路径可查看完整内容或更改，也可选择文件/文件夹；自定义路径独占替代默认候选，缺失时不回退读取默认目录，恢复默认不删除已有历史。配置卡片始终保留，不改变“有实际用量才进排行”的规则。

仅 `cursor` 与 `trae-code`（国际 IDE / SOLO）有手动凭据授权、同步、解除；不是官方 OAuth，而是实验性的私有 Dashboard 用量接口。凭据由当前 Windows 用户 DPAPI 加密到本机独立文件，不自动提取浏览器 Cookie；其他来源只有接入说明或真实导入，不出现假授权。保存凭据不等于验证成功，失败/过期仍可解除或重新授权。

当前默认请求最近 30 天，完整分页成功才原子发布同步缓存，再按真实 Token、时间、模型和稳定身份统计。空同步不生成零用量软件，缺少真实 Token 不从积分或金额推算；失败、取消或分页不完整保留旧缓存。新增两个同步通道属于原有两个来源，不增加 56 入口计数，也不意味着全部账户或全量历史已验证。详见 [连接说明](../docs/connections.md)。

连接状态只在运行内存保存，重启后已有可解密凭据显示“已保存，待验证”，需用户点击“同步”；没有后台远端自动同步。15 秒自动检查只刷新本地来源文件，不代表向这些账户接口定时请求。

## 全部 12 个模型家族

GPT；Claude（Opus / Sonnet / Haiku）；Gemini；DeepSeek；Qwen 千问；Kimi；GLM；豆包；MiniMax；混元；文心 ERNIE；Grok。

家族仅用于显示分组与价格规则组织。统计键使用来源提供的实际模型 ID、提供商和版本；同一家族下的新版本自动产生模型行，无需修改固定模型列表。国产 / 国际托管、自部署、本地推理、代理网关均保留实际提供商与别名依据。

Token 统计和费用估算独立：有有效 Token 但没有报价时仍可计量，费用显示未定价；未知模型独立一行，不根据软件品牌推断。图片、音视频、积分、请求次数等原始单位单独保留，不能伪装成 Token。

v0.3 以三源公开参考价目（LiteLLM、models.dev、OpenRouter）和少量 Cursor 官方核验记录估算实际 Token 对应的标准 API 价格。内置 2,011 条价目是“提供商 + 模型 + 来源”记录，包含同模型多来源报价，不是独立模型数量或采集上限。缓存读写、1 小时缓存写入和推理包含关系只计一次；明确长上下文档位按整次请求选择。手动费率优先补尚未定价记录，已定价历史固定完整价目，不因刷新变价。无法匹配或只有未分类总量时费用保持未知；估算不代表软件订阅实付，详见 [公开费率参考](../docs/pricing-reference.md)。

## 每项接入目标的完成标准

来源与版本验证、自动发现或授权配置、历史 / 增量导入、软件与模型归属、Token 口径映射、价格匹配与未定价状态、重复事件去重、零值与缺失区分均需验证。有用量后自动出现在总览、模型列表、趋势图、热力图和托盘，并遵循统一日期及币种。

当前开发版有 56 个配置入口，按上述三类分别标注，不能宣传“56 个全部自动采集”。每种已实现解析器都有格式回归，真实机器验证则要求本机真实记录，并单独报告版本、可读范围和软件/模型数量；CodeBuddy 等缺真会话的入口继续明确保留限制。最新实测见 [开发状态](../docs/development-status.md)。HTML 示例仍为 6 个软件、7 个已知模型及 1 类未知模型，与正式采集分开，不为未接入目标伪造用量。

统计界面只纳入所选日期/范围中 total > 0 的真实用量行；合法零值记录仍用于区分图表零消耗和未采集空白。软件中每个实际模型独立列表，分桶和占比条不重复累计软件小计。趋势与热力图点击日期只筛选下方列表，两个图表的日期位置均保持固定；默认展示趋势图，托盘仅保留图标、悬停摘要和菜单。

## 后续新增智能体与模型

26 个产品 / 平台和 12 个模型家族是保留的初始目标，当前 56 入口也不是固定上限。已实现的联网功能包括公开参考价目、自动公开汇率及上述两个特定 Dashboard 用量同步，不能据此声称已完成新软件自动发现、通用账号连接或自动适配。完整设计仍计划通过联网目录与按需搜索补充新软件的身份、官网、图标、模型元数据和用量来源；具体见 [联网发现与更新设计](online-discovery.md)。

新软件兼容现有格式时自动匹配经过验证的适配规则、新格式发布可信适配器更新，仍是后续设计需求。当前新模型可凭受支持格式中的真实调用 ID/时间、Token 和实际模型 ID 自动产生统计行，名称与价格随后独立匹配。发现、取得用量、匹配价格是独立状态；无有效用量仍不出现在总览或托盘。参考源码比 README 更多的最新模块也必须逐项核实，不能复制名称后就标成已采集。
